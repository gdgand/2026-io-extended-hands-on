Section 02 · Overview

App Function이란

앱의 핵심 기능을 시스템과 AI 에이전트가 호출할 수 있는 함수로
공개하는 Android API.

선언은 Kotlin 함수로

별도 스키마 언어나 서버 등록이 없습니다. 기존 함수에 @AppFunction을 붙이면 끝입니다.

설명은 KDoc으로

isDescribedByKDoc = true — 여러분이 이미 쓰던 주석이 그대로 LLM을 위한 함수 설명이 됩니다.

실행은 내 앱 안에서

내 앱 프로세스 안에서, 내 권한으로 실행됩니다. 화면을 띄우지 않고 백그라운드 실행도 가능합니다.

핵심 전환 · 지금까지 앱은 사람이 보는 화면을 제공했습니다. App Functions는 여기에 에이전트가 부르는 API라는 두 번째 표면을 추가합니다.

Section 02 · Use Cases

예시 ① 할일 관리 — 코드로 보기공식 문서 add-appfunctions의 createTask 예제. “할일로 추가해줘” 한 문장이 이 함수로 연결됩니다.

@RequiresApi(36) @AndroidEntryPoint @AppFunctionServiceEntryPoint( serviceName = "TaskAppFunctionService", appFunctionXmlFileName = "task_app_function_service", ) abstract class BaseTaskAppFunctionService : AppFunctionService() { @Inject internal lateinit var taskRepository: TaskRepository /** * Creates a task based on [createTaskParams]. * * @param createTaskParams The parameter to describe how to create the task. */ @AppFunction(isDescribedByKDoc = true) suspend fun createTask(createTaskParams: CreateTaskParams): Task = withContext(Dispatchers.IO) { if (createTaskParams.title == null && createTaskParams.content == null) throw AppFunctionInvalidArgumentException("Title or content should be non-null") val id = taskRepository.createTask(createTaskParams.title, createTaskParams.content) return@withContext taskRepository.getTask(id)?.toTask() ?: throw AppFunctionElementNotFoundException("Task not found for ID = $id") } }

KDoc = 함수 설명

isDescribedByKDoc = true — “Creates a task…” 주석이 그대로 에이전트가 읽는 명세가 됩니다.

// 파라미터 타입 (개념 예시) @AppFunctionSerializable data class CreateTaskParams( /** Title of the task. */ val title: String? = null, /** Content body. */ val content: String? = null, )
실패도 대화로 · 둘 다 비면 AppFunctionInvalidArgumentException을 던져, 에이전트가 사용자에게 다시 물어보게 합니다.

Section 02 · How it works

App Functions 작동 방식

① 선언 & 등록 — 제공하는 쪽

내 앱이 @AppFunction으로 선언한 함수가, 설치 시점에 AppFunctionManager(플랫폼)에 메타데이터로 색인됩니다.

② Retrieve — 조회하는 쪽

에이전트 앱이 “지금 이 기기에서 부를 수 있는 함수 목록”을 플랫폼에 요청합니다. 앱 이름을 미리 알 필요가 없습니다.

③ Select & Execute

모델이 사용자의 말과 함수 설명을 매칭해 하나를 고르고, 플랫폼을 통해 내 앱 프로세스에서 실행합니다.

Section 02 · How it works

두 개의 역할, 두 개의 관문오늘 우리가 만드는 것은 오른쪽 제공하는 쪽입니다.

CONSUMER

조회하는 쪽 — 에이전트 · 시스템 앱

아무 앱이나 다른 앱의 기능을 마음대로 부를 수 있으면 안 되겠죠. 그래서 권한이 관문입니다.

<uses-permission android:name= "android.permission.EXECUTE_APP_FUNCTIONS" />
  • 이 권한이 있어야 함수 목록 조회 · 실행이 가능합니다
  • 일반 앱은 받을 수 없는 제한된 권한입니다 (Gemini 같은 시스템 에이전트용)
  • 실습에서는 공식 agent 앱을 run_privileged.sh로 권한을 부여해 실행합니다
PROVIDER · 오늘의 주제

제공하는 쪽 — 우리 앱의 서비스

androidx.appfunctions 라이브러리의 어노테이션만으로 기능을 공개합니다.

  • Kotlin 함수 + 어노테이션 → KSP가 컴파일 타임에 처리
  • 메타데이터 XML과 호출 디스패처 코드가 자동 생성됩니다
  • 리플렉션 없음 · 런타임 등록 없음 → 앱 설치만으로 시스템이 인지
잠시 뒤 어노테이션 프로세싱으로 생성되는 XML도 직접 열어봅니다.

Section 02 · Annotations

@AppFunctionServiceEntryPointApp Function들을 담을 서비스를 선언합니다. — ChatApp 샘플 실제 코드

@RequiresApi(36) @AndroidEntryPoint // Hilt 주입 사용 @AppFunctionServiceEntryPoint( serviceName = "ChatAppFunctionService", // 생성될 Service 클래스 이름 appFunctionXmlFileName = "chat_app_function_service", ) abstract class BaseChatAppFunctionService : AppFunctionService() { @Inject lateinit var messageRepository: MessageRepository @Inject lateinit var recipientsRepository: RecipientsRepository @Inject lateinit var callManager: CallManager // ... 여기에 @AppFunction 함수들이 들어갑니다 }

왜 abstract 인가요?

KSP가 이 클래스를 상속한 구현 서비스(ChatAppFunctionService)를 생성합니다. 우리는 비즈니스 로직만 씁니다.

DI를 그대로 쓸 수 있습니다

@AndroidEntryPoint + @Inject — 기존 Repository 계층을 그대로 재사용합니다. App Function을 위해 아키텍처를 바꿀 필요가 없습니다.

appFunctionXmlFileName

생성될 메타데이터 XML 파일명. Manifest의 android.app.appfunctions.v2 값과 짝을 맞춥니다.

Section 02 · Annotations

@AppFunction · isDescribedByKDocKDoc이 곧 LLM에게 전달되는 함수 명세가 됩니다.

/** * Send a text message with optional image attachments to an individual contact or group. * Required workflow: Call "searchContacts" first to obtain a valid endpointValue. * * @param endpointValue The unique identifier for the recipient or group. * @param messageBody The text content of the message. Cannot be empty or blank. * @param imageUris Optional list of image URIs to attach to the message. * @return A human-readable message indicating the error or confirmation. * @throws AppFunctionInvalidArgumentException If messageBody is blank. If thrown, * ask the user to provide the message content to send. * @throws AppFunctionElementNotFoundException If no contact matches endpointValue. * If thrown, call "searchContacts" to find the correct ID. */ @AppFunction(isDescribedByKDoc = true) suspend fun sendMessage( endpointValue: String, messageBody: String, imageUris: List<Uri>? = null, ): String { if (messageBody.isBlank()) throw AppFunctionInvalidArgumentException("Message body cannot be empty") // ... return "Message sent to: $displayName." }
주석을 LLM에게 쓴다고 생각하세요.
“이 함수를 언제 부르는지”, “실패하면 사용자에게 뭐라고 물어봐야 하는지”까지 적습니다.

워크플로를 명시

“Call searchContacts first” — 함수 간 호출 순서를 문장으로 알려주면 모델이 그 순서를 지킵니다.

예외도 복구 지시로

@throws에 “If thrown, ask the user to…”를 적으면, 실패가 대화의 다음 질문으로 이어집니다.

값 제약

@AppFunctionStringValueConstraint(enumValues = [...])로 허용 값을 못 박을 수 있습니다.

/** Represents a result from a contact or group search. */ @AppFunctionSerializable(isDescribedByKDoc = true) data class ContactSearchResult( /** The human-readable name of the contact or group. */ val contactDisplayName: String, /** The type of the found entity, either "INDIVIDUAL" or "GROUP". */ val contactType: String, /** The unique identifier of the endpoint. */ val endpointValue: String, /** The human-readable label/display name of the endpoint. */ val endpointDisplayName: String, ) /** Represents the search results for a specific chat endpoint. */ @AppFunctionSerializable(isDescribedByKDoc = true) data class MessagesSearchResult( val endpointValue: String, val messages: List<Message>, // 중첩도 가능 )

프로퍼티 KDoc도 읽습니다

각 필드 위 주석이 그대로 필드 설명으로 XML에 들어갑니다. 모델이 값을 잘못 채우는 걸 막아줍니다.

지원 타입

  • 기본형: String Int Long Double Float Boolean
  • List<T>, nullable, 기본값
  • Uri, PendingIntent 같은 Android 타입
  • 다른 @AppFunctionSerializable 중첩
PendingIntent 반환 · ChatApp의 makeCall은 PendingIntent를 돌려줍니다. 에이전트가 “여기서부터는 앱 화면에서 이어가세요”라고 넘길 수 있습니다.

// build.gradle.kts plugins { id("com.google.devtools.ksp") } android { compileSdk = 36 // 36 이상 필수 } dependencies { implementation("androidx.appfunctions:appfunctions:1.0.0-alpha10") // Kotlin 소스를 쓴다면 KSP로 컴파일러를 추가 ksp("androidx.appfunctions:appfunctions-compiler:1.0.0-alpha10") }

멀티 모듈이라면

함수를 여러 모듈에 나눠 두었다면, 앱 모듈에서 이를 합쳐주는 aggregate 단계가 필요합니다. ChatApp 샘플은 appfunctions.aggregateAppFunctions 컨벤션 플러그인으로 처리합니다.

<!-- AndroidManifest.xml --> <service android:name="com.example.chatapp.appfunctions.ChatAppFunctionService" android:permission="android.permission.BIND_APP_FUNCTION_SERVICE" android:exported="true" tools:targetApi="36"> <property android:name="android.app.appfunctions.schema" android:value="app_functions_schema.xsd" /> <property android:name="android.app.appfunctions.v2" android:value="chat_app_function_service.xml" /> ← 생성된 XML <intent-filter> <action android:name="android.app.appfunctions.AppFunctionService" /> </intent-filter> </service>

exported = true 인데 안전한가요?

네. BIND_APP_FUNCTION_SERVICE 권한을 가진 시스템만 바인딩할 수 있습니다. 일반 앱은 접근할 수 없습니다.

android:name

@AppFunctionServiceEntryPoint(serviceName = …)에 적은 이름으로 클래스가 생성됩니다. 그 이름을 그대로 씁니다.

appfunctions.v2

appFunctionXmlFileName에 적은 파일명 + .xml. 두 값이 어긋나면 함수가 노출되지 않습니다.

Section 02 · Implementation tips

구현할 때 꼭 기억할 두 가지

TIP #1

suspend 함수를 쓸 수 있습니다

App Function은 기본적으로 UI 스레드에서 실행됩니다. 네트워크·DB 작업이 있다면 반드시 suspend로 선언하고 적절한 디스패처로 전환하세요.

@AppFunction(isDescribedByKDoc = true) suspend fun searchMessages(query: String): List<MessagesSearchResult> = withContext(Dispatchers.IO) { repository.search(query) // 무거운 작업은 여기서 }
주의 · 오래 걸리는 작업은 타임아웃될 수 있습니다. 즉시 PendingIntent를 돌려주고 나머지는 앱 화면에서 이어가는 패턴도 고려하세요.
TIP #2

노출 여부를 런타임에 제어할 수 있습니다

로그인하지 않은 사용자, 무료 플랜, 아직 준비 중인 기능 — 상황에 따라 특정 함수만 숨길 수 있습니다.

val manager = AppFunctionManager.getInstance(context) manager?.setAppFunctionEnabled( functionId = "…BaseChatAppFunctionService#makeCall", newEnabledState = AppFunctionManager.APP_FUNCTION_STATE_DISABLED, ) // STATE_DEFAULT(0) — XML의 enabledByDefault 값을 따름 // STATE_ENABLED(1) / STATE_DISABLED(2) — 명시적 재정의 val enabled = manager?.isAppFunctionEnabled(functionId)
기본값은 @AppFunction 선언 시점에 XML의 <enabledByDefault>로 굳고, 이 API는 그 위에 사용자/앱 상태별 재정의를 얹습니다.

Section 02 · Verify

통합 확인 adb shell cmd app_function앱을 설치한 뒤, 시스템이 내 함수를 실제로 부를 수 있는지 확인합니다.

adb
# 메시지 전송 함수를 시스템 에이전트처럼 직접 실행 $ adb shell "cmd app_function execute-app-function \ --package com.example.chatapp \ --function 'com.example.chatapp.appfunctions.\ BaseChatAppFunctionService#sendMessage' \ --parameters '{\"endpointValue\": \"1\", \"messageBody\": \"Hello Alice!\"}'" # 연락처 검색 $ adb shell "cmd app_function execute-app-function \ --package com.example.chatapp \ --function '…#searchContacts' \ --parameters '{\"query\": \"Alice\", \"contactType\": \"INDIVIDUAL\"}'" # 에이전트 허용목록 캐시 비우기 (함수가 안 보일 때) $ adb shell cmd app_function purge-allowlist-cache

이걸로 확인되는 것

  • 서비스가 Manifest에 제대로 등록됐는지
  • 파라미터 직렬화가 맞는지
  • 함수 본문이 기대대로 동작하는지

이걸로 확인되지 않는 것

이 명령은 내가 이미 스펙을 알고 파라미터를 직접 채워 넣는 방식입니다.

우리가 진짜 원하는 건 Gemini 같은 에이전트가 내 함수를 스스로 발견해서, 사용자의 한 문장으로 여러 앱을 넘나드는 워크플로를 수행하는 것입니다.

그래서 다음 단계 · 공식 agent 앱으로 “진짜 에이전트가 부르는” 경로를 확인합니다.

Section 03 · Step 1

hands-on
# 1. 공식 샘플 저장소 클론 $ git clone https://github.com/android/appfunctions.git $ cd appfunctions # 2. 에뮬레이터 실행 (섹션 1에서 만든 것) $ android emulator start medium_phone # 3. ChatApp 설치 — Android Studio로 열어 Run 'app' $ cd ChatApp # 4. Agent 앱이 하는 일

플랫폼에 등록된 App Function 목록을 조회하고, 수동 입력 또는 LLM 에이전트 두 방식으로 실행해봅니다. 통합 문제 진단(troubleshoot) 기능도 있습니다.

왜 privileged 실행이 필요한가요?

EXECUTE_APP_FUNCTIONS는 일반 앱이 받을 수 없는 권한이라, 스크립트가 shell 신원으로 권한을 부여해 실행합니다.

체크리스트 · 함수가 목록에 안 보이면 ① API 36+ 인지 ② Manifest의 XML 파일명이 맞는지 ③ purge-allowlist-cache 순으로 확인하세요.
